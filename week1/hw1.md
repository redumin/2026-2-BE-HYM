# 과제: 주문 도메인 분석해보기

처음이라 어려울 수 있어요! 너무 부담갖지 말고 생각나는 대로 자유롭게 작성해보아요. 점수를 내고 채점하고 그러지 않습니다… ㅎㅎ

---

예시로 오늘 배운 Product를 한 번 분석해 볼게요.

### 1. 핵심 용어
Product와 관련해서 자주 나오는 단어와 뜻을 한 번 생각해볼까요?  
우선 Product 자체, 상품이라는 것이 있을 거에요. 상품은 무엇을 가지고 있을까요?
재고도 있고, 가격도 있고, 또...

- 상품(Product): 판매하는 물건 하나.
- 재고(stock): 지금 팔 수 있는 수량.
- 가격(price): 상품 하나의 판매 금액
- 판매 상태: 이 상품을 지금 살 수 있는지 나타내는 값
- 재고 차감: 주문이 들어와 재고를 줄이는 일
- 품절: 재고가 0이 되어 더 팔 수 없는 상태

### 2. 주요 행위
누가 무엇을 하는지 "누가 ~ 한다" 형태로 적으면 쉬워요.
우리 시스템에는 크게 판매자, 구매자, 시스템이 있을 것 같아요.
그래서 세 가지 역할로 나누어서 떠올려 봤어요.

- 판매자는 상품을 등록할 수 있다.
- 판매자는 상품 판매를 중지할 수 있다.
- 구매자는 상품을 조회할 수 있다.
- 구매자는 상품을 주문할 수 있다.
- 시스템은 재고가 0이 되면 그 상품을 품절 처리한다.

### 3. 상태와 상태 전이
상품은 어떤 상태가 있을수 있을까요?

상태는 판매중, 판매 중지, 품절이 있을 수 있다.

- 판매중 → 품절: 재고가 0이 되는 순간이다.
- 판매중 → 판매중지: 판매자가 언제든 바꿀 수 있다. 재고가 남아 있어도 가능하다.
- 품절 → 판매중: 재입고가 된다면 판매중으로 바뀔 수 있다.
- 판매중지 → 판매중: 판매자가 재개하면 판매중으로 바뀔 수 있다.

### 4. 비즈니스 규칙
상품이 가지고 있어야 할 규칙들을 생각해봐요.
달리 생각해보면, 우리가 작성한 아래 규칙이 없으면 서비스가 엉망이 될 수도 있는 거에요!

- 주문 수량은 1개 이상이어야 한다.
- 재고보다 많은 수량은 주문할 수 없다.
- 재고가 0이 되면 상품의 상태를 품절로 바꾸어야 한다.
- 재고는 음수가 될 수 없다.
- 가격은 음수가 될 수 없다.

### 5. 잘못된 상황
위 4번 규칙을 제대로 구현해내지 못하면 실제로 무슨 일들이 일어날까요?

- 재고가 3개뿐인데 5개가 팔린다.
- 재고가 0인 상품에 주문이 들어온다.
- 재고가 0인데 판매중으로 표시된다.
- 주문서에 0개를 사겠다는 주문이 들어온다.

### 6. 규칙을 담당할 객체 후보
규칙을 판단하려려면 어떤 정보들이 필요할까요? 그리고 그 정보는 누가 가지고 있을까요?

- 주문 수량은 1개 이상이어야 한다. : Product는 아닌 것 같다. 수량은 상품의 속성이 아니라 주문 쪽 속성 같다. Order 아닐까?
- 재고보다 많은 수량은 주문할 수 없다. : 재고를 아는 곳은 Product이니 이 규칙은 Product가 지켜야 할 것 같다.

…

## 여기서부터 작성해주시면 됩니다.

### 1. 핵심 용어

ex) 주문, 주문 항목, 배송지, …

-주문(Order): 구매자가 상품을 구매하기로 확정하고 생성하는 거래 요청.
-주문 항목(Order Item): 한 주문 안에 담긴 상품들과 선택한 수량, 금액 정보.
-주문 번호(Order ID): 각 주문을 식별하기 위한 고유한 번호.
-총 주문 금액(Total Amount): 주문한 상품들의 금액 합계(+ 배송비 등).
-결제(Payment): 주문 금액을 실제로 지불하는 행위.
-배송지(Shipping Address): 주문한 상품을 수령할 주소 및 수령인 정보.

### 2. 주요 행위

ex) 주문 항목을 추가한다.

-구매자는 장바구니에 주문 항목을 추가할 수 있다.
-구매자는 장바구니나 상품 페이지에서 주문을 생성할 수 있다.
-구매자는 주문 시 배송지와 결제 수단을 선택할 수 있다.
-구매자는 배송 시작 전에 주문을 취소할 수 있다.
-시스템은 주문이 접수되면 상품의 재고를 차감한다.
-시스템은 결제가 성공하면 주문을 '결제 완료' 상태로 전환한다.
-판매자는 결제 완료된 주문을 확인하고 배송을 시작할 수 있다.

### 3. 상태와 상태 전이

ex) 주문됨 → 배송중: 배송을 시작한다.

상태: 주문 생성(접수), 결제 대기, 결제 완료, 배송 준비중, 배송중, 배송 완료, 주문 취소

-주문 생성 → 결제 대기 / 결제 완료: 구매자가 주문을 넣고 결제 프로세스를 진행할 때 전환된다.
-결제 완료 → 배송 준비중 / 배송중: 판매자가 주문을 확인하고 출고 조치를 시작하면 전환된다.
-배송중 → 배송 완료: 택배사를 통해 물품 전달이 끝나면 전환된다.
-결제 완료 → 주문 취소: 상품이 발송되기 전, 구매자가 취소 요청을 하거나 재고 부족 등의 사유로 시스템이 취소 처리할 때 전환된다. (이 때 차감된 재고는 다시 복구되어야함.)

### 4. 비즈니스 규칙

ex) 주문 항목의 수량은 1개 이상이어야 한다.

-주문은 최소 1개 이상의 주문 항목을 포함해야 한다.
-주문 생성 시점의 상품 가격(주문 당시 금액)을 기록해야 한다. (나중에 상품 가격이 변경되어도 기존 주문서의 가격은 변하지 않아야 함)
-주문 총 금액은 각 주문 항목의 (수량 × 주문 당시 단가 + 배송비)의 합과 일치해야 한다.
-결제가 완료되기 전까지는 배송을 시작할 수 없다.
-이미 배송이 시작된(배송중) 주문은 취소할 수 없다.

### 5. 잘못된 상황

ex) 주문 항목이 0개인 주문이 생성된다.

-주문이 취소되었는데 재고가 복구되지 않아 실제 재고와 시스템 재고가 맞지 않는다.
-상품 가격이 인상되었을 때, 이전에 생성된 주문서의 금액까지 같이 올라간다.
-결제가 이루어지지 않았는데 배송 준비 단계로 넘어간다.
-이미 택배에 실려 배송 중인 상품인데 주문 취소 처리가 가능하다.
-아무 상품도 담기지 않은 0원짜리 빈 주문서가 생성된다.

### 6. 규칙을 담당할 객체 후보

ex) 주문의 총액은 각 주문 항목 금액의 합이어야 한다. : 항목을 전부 가진 것은 주문 뿐이니 주문이라고 생각합니다.

-주문은 최소 1개 이상의 주문 항목을 포함해야 한다. : 주문 항목들을 목록으로 들고 있는 주체는 주문임. 주문이 만들어질 때 내부에 항목이 하나라도 들어있는지 검사하는 책임은 주문이 가져야 함.
-주문 생성 시점의 상품 가격(주문 당시 금액)을 기록해야 한다. (나중에 상품 가격이 변경되어도 기존 주문서의 가격은 변하지 않아야 함) : Product의 현재 가격은 언제든 바뀔 수 있음. 따라서 주문이 이루어지는 순간 특정 상품의 '당시 가격'과 '수량' 정보를 따로 보관해 두는 것은 주문 항목의 역할임.
-주문 총 금액은 각 주문 항목의 (수량 × 주문 당시 단가 + 배송비)의 합과 일치해야 한다. : 주문 항목들을 목록으로 들고 있는 주체는 주문임. 즉, 주문 객체가 모든 주문 항목의 금액을 더하고, 배송비 정책을 반영하여 최종 주문 총액을 계산해야함.
-결제가 완료되기 전까지는 배송을 시작할 수 없다. : 주문의 현재 상태를 관리하는 곳은 주문 객체임. 배송을 시작하는 행위(배송 객체 생성 등)를 처리할 때 주문의 상태가 '결제 완료' 상태인지 확인하는 규칙은 주문이 검증해야 함.
-이미 배송이 시작된(배송중) 주문은 취소할 수 없다. : 주문 취소 요청이 들어왔을 때, 해당 주문의 현재 상태를 알고 있는 것은 주문 객체임. 따라서 취소 가능 여부를 판단하고 거절할 책임은 주문에게 있음.
