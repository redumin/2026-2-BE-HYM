1.Dockerfile, 이미지, 컨테이너는 각각 어떤 역할을 하나요?
Dockerfile : 이미지를 만드는 방법을 적어둔 파일
이미지 : 소스 코드와 실행 환경이 하나로 압축되어 있는 상태
컨테이너 : 이미지로 실행한 인스턴스

2.AWS와 EC2는 각각 무엇인가요?
AWS, Amazon Web Service : 서버 등 IT 자원을 제공하는 클라우드 서비스
EC2 : AWS에서 사용할 수 있는 가상 서버

3.외부에서 EC2에 배포한 API를 호출할 때, IP 주소와 포트는 어떤 역할을 하나요?
IP 주소 : 인터넷 네트워크상에서 EC2 가상 서버의 위치를 식별하는 주소
포트 : 서버 내부에서 실행 중인 여러 프로그램 중 어느 애플리케이션으로 들어갈지 지정해 주는 번호

4.실제 서비스를 운영할 때 서버 외에 어떤 것들이 필요할까요?
데이터베이스 : EC2 서버와 DB를 분리하여 데이터 안전성과 확장성을 확보하는 서비스 (예 : AWS RDS)
모니터링 & 로깅 : 서버 상태(CPU, 메모리 사용량)와 애플리케이션 에러 로그를 실시간 추적하는 도구 (예 : AWS CloudWatch, Datadog)
보안 환경: IP 및 포트 접근 권한을 제어하는 방화벽 및 가상 네트워크 설정

5.사용자가 많아져 서버 한 대로 요청을 감당하기 어려워진다면 어떻게 할 수 있을까요?
Scale-Up (수직 확장) : 가상 서버의 CPU, RAM 스펙을 더 고성능 사양으로 올려 처리 능력을 키우는 방법
Scale-Out (수평 확장) + 로드 밸런싱 : 동일한 사양의 EC2 서버를 여러 대 증설하고, 맨 앞에 로드 밸런서를 배치하여 들어오는 요청을 각 서버로 균등하게 분산 처리하는 구조

6.이번 실습에서 사용한 EC2 외에, 애플리케이션을 배포할 수 있는 다른 방법에는 무엇이 있을까요?
EC2는 빈 가상 컴퓨터만 제공하며, 사용자가 OS 선택, 방화벽 설정, Docker/Java 설치, 서버 실행까지 직접 관리해야하는 IaaS 방식
개발 및 배포에 필요한 플랫폼과 런타임 환경까지 함께 제공하는 서비스인 PaaS를 고려할 수 있다. (예 : Railway, Render, Fly.io)
