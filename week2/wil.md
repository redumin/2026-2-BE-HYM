2주차 핵심 개념 : DDD
DDD(Domain-Driven Design) : 도메인별로 나누어 개발하자
도메인 : 다루는 업무 영역
entity와 value object의 차이 : entity는 id를 통해 구분 가능, value는 구분 불가(ex-만원 지페의 일련번호로 구분하는 일이 거의 없음, 만원은 다 같은 만원)
에시) price 객체 -> long으로 표현 가능하지만, 객체를 따로 만들면 추가적인 규칙을 service에 구현할 필요 없이 price의 범위 제한 가능

aggregate : 객체들의 집합을 의미
aggregate root : aggregate를 대표하는 단일 진입점 엔티티
-> DDD의 가장 주요한 아이디어(서로의 도메인을 존중, 격리시키는 것, 독립적으로 다루는 것, 최소한의 참조)를 구현하기 위한 단위로써 작용

불변식 : 객체가 살아있는 동안 항상 참이어야하는 조건
-> 정적 팩토리 메서드를 이용하면 객체 생성 시점에 유효성을 검증한 후, 정상적인 상태의 객체만 반환하거나 예외를 발생시키므로 항상 불변식을 충족하는 완벽한 객체만을 보장
-> 생성자 (of, create, place 등) 사용

package private : 접근 제어자(Access Modifier)를 명시하지 않았을 때 기본(Default)으로 적용되는 접근 수준을 의미, 같은 패키지 내부는 자유롭게 접근 및 호출 가능하지만 다른 패키지는 접근 불가능
-> "같은 패키지 안에 있는 클래스들끼리만 공유하는 비밀" 수준의 접근 제어자

long 대신 BigDecimal 사용하는 이유 : long 타입은 정수 값만 표현 가능하지만 실무에서는 3.5% 할인, 달러/원 환율 등 소수점 연산 필요, 메모리가 허용하는 한 BigDecimal은 제한의 정수 및 소수점을 표현 가능, 관련 연산을 BigDecimal 전용 유틸리티나 도메인 객체로 감싸면 "돈/화폐/정밀 수치 계산을 다루는 변수"라는 의미가 도메인 관점에서 명확해지는 장점
