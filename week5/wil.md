주요 주제 : 주문 목록이 잘 뜬다고 해서 데이터를 가져오는 과정이 효율적이라고 할 수 있을까?
기존 코드로 주문 목록과 총액을 한번의 sql로 조회하는지 test해보면 결과는 10개의 주문에 대해 11번의 조회 SQL이 이루어지는 것을 알 수 있었다.
결과가 틀린 것이 아닌 결과를 만드는 과정에서 예상보다 많은 SQL이 실행된다는 문제가 있는 것이다.
실습 코드의 경우 Order의 totalAmount()가 OrderItem::subtotal로 주문(OrderItem)을 순회하며 각 항목의 subtotal을 더하는 방식인데,
아직 가져오지 않은 주문 항목을 여기서 사용하므로 collection을 읽는 과정에서 항목 조회 SQL이 발생하는 것이다.
그렇다면 왜 컬렉션을 사용하는 시점까지 조회를 미루는 것일까?
→ 객체와 테이블의 연결 방식이 다르다. 객체는 참조로 연결되고, 테이블은 외래 키로 연결되는데, JPA는 테이블의 데이터를 객체 관계로 연결해준다.
지연 로딩 LAZY : 연관 데이터를 실제로 사용할 때에 조회 -> 주문을 조회하는 시점에는 주문 항목을 바로 가져오지 않는다.
즉, Hibernate가 관리하는 컬렉션을 통해서 내용이 필요한 시점에 조회가 일어날 수 있도록 설정하는 것
조회된 주문 N건의 연관 데이터를 N개 추가 조회하는 현상을 N + 1 문제라고 하며, 이를 줄이는 두가지 방식이 바로 Fetch Join과 Batch Size 방식이다.

[아래는 과제 요구사항 질문들]
1. 주문 수를 10건에서 20건으로 늘렸을 때, Fetch Join과 Batch Size의 SQL 개수는 각각 어떻게 달라졌나요? 실제 실행 결과를 기록하고, 두 방식의 조회 원리와 연결하여 이유를 설명해주세요.
-> 기존에 주문 수가 10건일 때는 Fetch Join은 1개의 조회 SQL문이 필요했고, Batch Size 방식은 2개의 조회 SQL문이 필요했다.
   주문 건수를 20개로 늘리면 Fetch Join 방식은 여전히 1개의 조회 SQL문을 필요로 하고, Batch Size 방식은 3개의 SQL문을 필요로 했다.
   이는 Batch Size는 하위 데이터를 가져올 때 IN (?, ?, ...) 안에 들어갈 파라미터를 최대 몇 개 단위로 쪼갤 것인지를 결정하는 설정이기 때문이다.
   Fetch Join은 연관된 엔티티나 컬렉션을 SQL 한 번에 함께 조회(즉시 로딩)해 오는 방법이므로 주문 건수가 늘어나거나 줄어들어도 조회 SQL문은 1개로 고정된다.
   반면 Batch Size 방식은 주문이 100개인데 Batch Size가 그대로 10이라면, 아이템을 가져오는 IN 쿼리만 10번이 반복되어 총 11개의 쿼리가 발생하게 된다.
2. 이번 실습에서는 Fetch Join의 SQL 개수가 더 적었습니다. 이것만으로 Fetch Join이 항상 더 좋은 방법이라고 할 수 있을까요? 두 방식의 특징을 바탕으로 어떤 점을 고려하여 선택해야 할지 설명해주세요.
-> Fetch Join은 연관된 엔티티를 SQL 한 번(JOIN)에 전부 끌어오기 때문에, N+1 문제를 근본적으로 해결하고 단일 조회 성능이 매우 뛰어나다.
   그러나 1:N 관계(예: 주문과 주문 항목)에서 Fetch Join을 사용하면 데이터가 뻥튀기(중복)되어 조회되는 문제가 발생한다.
   즉, 연관된 데이터가 너무 많을 경우 한 번에 너무 많은 데이터를 불러와서 애플리케이션 서버 메모리에 부담을 줄 수 있다.
   때문에 등장한 방식이 Batch Size 방식이다. 두 방식은 각각 장단점이 존재하기에 상황에 따라 잘 저울질하며 사용해야한다.
   우선 데이터의 총량이 적거나 적당한 경우에는 Fetch Join이 유리하다. 네트워크 전송량이나 메모리 부하가 미미하므로 Fetch Join을 써서 쿼리 1개로 깔끔하게 가져오는 것이 유지보수와 성능 모두에 좋다.
   반면 데이터 양이 매우 많고 페이징(Paging)이 필요한 경우에는 Batch Size 방식이 유리하다.
   데이터가 뻥튀기된 상태에서 페이징을 처리하면 하이버네이트가 메모리 경고를 띄우거나 잘못된 페이징 결과를 낼 수 있다.
   이럴 때는 조인으로 행을 늘리지 않고, 주문을 먼저 10개 딱 끊어서 가져온 뒤 Batch Size로 아이템을 쪼개서 가져오는 방식이 훨씬 안전하다.
